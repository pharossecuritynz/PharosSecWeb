# Document Control Register

A log of when major documents/sections in this project were created and last substantively reviewed. Update this when you make a meaningful revision (not for typo fixes) — it keeps the whole studio trustworthy as a "living" operating system rather than a one-time snapshot.

## How to use this register

- Add a row when a new document is created or substantially rewritten
- Update the "Last reviewed" date whenever you revisit and confirm (or revise) a document
- Use the "Status" column to flag documents that still need founder input vs. ones that are launch-ready

## Review cadence recommendation

- **Brand and positioning documents:** review every 6–12 months, or after any major strategic shift
- **Service definitions and pricing:** review quarterly for the first year (real delivery data will sharpen these fast), then every 6 months
- **Operating manual:** review after any process pain point surfaces in real delivery
- **Templates:** review after each of the first 3–5 uses of each template, incorporating real lessons learned
- **Agent prompts:** review whenever the source documents they reference change materially
