# Service Catalogue

**Revised 2026-09-09 under the commercial-validation pivot.** See `00-business/pharos-current-strategy.md` for the full reasoning. This pass categorises every service by whether it's part of the active 90-day validation offer; it does not change most of the underlying scope work from the 2026-08-22 Pharos v2 pass, which consolidated eight flat services to seven and is otherwise still the working detail behind each service file.

## Category key

- **ACTIVE NOW** — actively sold and pitched during the validation window.
- **SUPPORTING FEATURE** — part of how the active offer is sold or delivered, not a separate product with its own pricing/sales motion.
- **BUILD LATER** — a real, fully-designed service, not thrown away, but not actively pitched cold right now. Revisit once demand or delivery volume justifies it.
- **REMOVE FROM ACTIVE STRATEGY** — none currently; nothing in the existing catalogue was judged a distraction or duplicate worth dropping outright. See `09-project-management/build-now-later-stop.md` for the equivalent audit of tools, agents, and website features, where several items do fall into this category.

## The active offer, in one line

**One core paid service, sold through two entry triggers, plus one lighter paid follow-on.** Independent Security Review is the engagement; IT Provider Security Assurance is the same engagement pitched to a client whose real question is about their MSP; Remediation Assurance is what happens next once findings need independently verifying. Everything else in the table above is real, designed work that stays on the shelf until evidence says it's worth actively selling.

## Service selection guide (for discovery calls)

| If the client says... | Recommend |
|---|---|
| "What does our business actually look like from the outside?" | Exposure Snapshot (free, then discuss the review) |
| "We don't know where we stand" | Independent Security Review |
| "Our MSP says we're covered, how do we know that's true?" | IT Provider Security Assurance (same review, this framing) |
| "We've had the review, how do we know the fixes happened?" | Remediation Assurance |
| "We don't have a plan if something goes wrong" | Note it as a scope item inside the Independent Security Review; Incident Readiness as a standalone offer is BUILD LATER |
| "We've done a review, now what?" (wanting a fuller coordinated programme, not just verification) | Secure Foundations — BUILD LATER, discuss as a future step, don't actively pitch it cold |
| "We want someone to call when questions come up" | Security Adviser — only raise this after a review has demonstrated value, never as the opening pitch |
